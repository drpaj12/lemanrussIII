# Seeker-Si: a standard-cell (silicon) Seeker set, spec (2026-11-05)

Status: phase 1 (spec only). No code, no circuits. Phase 2 (3-circuit pilot on mmuart) and phase 3
(100 circuits) wait for the controller's go.

Purpose: Leman Russ III research question RQ1.1, which structures in a netlist do not belong to the
claimed design, asked at the standard-cell level, the form a fab or a scanned chip is checked in.
Measure: a gated release of 100 circuits (clean/infected, hidden mix), reported as a NEW set.
Peter, 2026-11-05, verbatim: "I want to make a seeker's for the silicon flow where the trojans are
added simple HT at the lowest level (only 1-3 trojans) the problem with this is obfuscation
techniques. Maybe we should just do it with the ABC approach as the other ones as another set of
100 with a difference compared to Lut4 and Lut6 - These won't have the same benchmarks as the
other set, so make this known."

## 0. Not comparable with Seeker comb/seq/proc

Seeker-Si uses **different bases** (section 3), a **different cell library** (sky130_fd_sc_hd
standard cells, not 2-input AND/OR/INV nor K-input LUTs) and a **different gate** (section 6).
Do not compare per base, per form, or by AUROC with the comb, seq or proc sets. This statement goes
into the README, the manifest (`family: silicon`, `bases: [...]`) and the results doc.

## 1. Form

One form, `silicon`: a netlist of `sky130_fd_sc_hd__*_1` cells (84 cell types in
odin3 `lib/sky130hd.o3lib`, including `dfxtp_1` as the only flip-flop), one `.model top`/module
`top`, file in Verilog (cell instances, so the cell type is visible) with an equivalent
gates-as-names BLIF kept for the checkers. Constants use `conb_1` tie cells exactly as the silicon
flow's `netlist` step does, for every circuit. Optional later: GDS for a subset through the full
flow (not in this spec's gate; the ladder shows OpenROAD stops on wb_lcd and des).

## 2. Trojans at cell level

1 to 3 per infected circuit (P = 0.5, 0.3, 0.2, as the other families), each simple, small, built
from std cells on existing nets of the clean cell netlist (Odin III `gates.blif`, where every
`.names` is one sky130 cell). Existing HTL kinds that fit, mapped to cells:

| HTL kind | cell realisation |
|---|---|
| trigger `t-comb-rare` | AND of k rare-valued nets (k to give p < 1e-2/1e-3/1e-4), as a tree of `and4`/`nand4`/`nor4` plus `inv`/`*b` cells |
| trigger `t-seq-counter` | n-bit counter: `dfxtp_1` plus `xor2`/`and2` half adders, fires at a terminal count |
| trigger `t-seq-pattern` | FSM pattern: a few `dfxtp_1` plus a comparator tree |
| payload `p-dos-stuck` | victim net forced to its minority value: `and2b`/`or2b` or `mux2` |
| payload `p-err-hi`, `p-err-lo` | flip of a victim output (upper/lower half of the output list): `xor2` |
| payload leak (new, agent default) | `mux2` that substitutes an internal bit onto an existing output when triggered |

Dropped, as in the n200 design: `p-energy` and `p-slowdown` (removed by logic optimisation, no
witness after re-mapping). Rules carried over: pairwise disjoint trigger net sets, different victims,
every Trojan has its own witness, equivalent to the reference when all triggers are forced inactive.
The leak payload is new for this set; it is built only if its witness (internal bit visible at the
output on the trigger) can be stated and replayed, otherwise left out and recorded.

Insertion reuses `lemanruss.htl.insert_netlist` on the cell netlist read as `.names` BLIF; the new
cells enter as covers that are single sky130 functions, so "at the lowest level" holds before
obfuscation.

## 3. Bases

Only designs that pass the Odin III silicon flow `map` and `equiv` steps (odin3
`docs/results/silicon-ladder-opencores.md`, 2026-11-04). The set is the netlist form, so GDS is not
required for a base to qualify.

| base | cells | map + equiv | status for Seeker-Si |
|---|---|---|---|
| mmuart | 488 | ok, equivalent | in (pilot base, smallest) |
| simple_spi | 687 | ok, equivalent | in |
| i2c | 979 | ok, equivalent | in |
| des | 18686 | ok, equivalent (stops later at OpenROAD route) | candidate, large; decide at phase 3 on gate time |
| wb_lcd | 3020 | map ok, equiv UNDECIDED (dsec) | out unless `scorr-cec` proves it |
| verilog_cordic_core | 7534 | map killed at 6 GiB | out (re-run only if a lower-memory map exists) |
| sha3_low | 17565 | map killed at 6 GiB | out (same) |
| Seeker-Proc bases | 1310+ FFs | not run through silicon map | out unless they pass; never named in this repo's private set |

Expected: 3 bases certain, up to 4 with des. 100 circuits spread across them, smallest base first
(about 33 each at three bases). Small bases give few distinct structures after optimisation, so a
base that cannot supply its share has fewer, listed, never padded (n200 distinctness rule).
Caveat recorded from the ladder: mmuart `final.v` fails its own iverilog testbench with x values
(42 of 61 checks) because `dfxtp_1` has no reset, so iverilog on the cell netlist is judged by
clean-twin vs infected-twin trace equality, never by testbench pass.

## 4. Obfuscation recipe and mapping

The same recipe as the other families (`lemanruss.htl.obfuscate`, spec n200 section 4), with the
mapping step swapped for the silicon flow's own:

1. Insert the Trojans into the clean cell netlist (section 2) giving `pre`.
2. Random ABC script per circuit, one distribution for clean and infected: `strash`, 1 to 8
   operations from the same `OPS` list (balance, rewrite, refactor, resub, dc2, drw, drf, ifraig,
   with their variants), optional `dch -f`, then `map -a` or `map`.
3. Mapping by Odin III, **the silicon flow's own**: `read_techlib lib/sky130hd.o3lib`, then
   `read_blif`, then `abc --gates sky130hd --script <script>`, then `dfflibmap sky130hd`. This is the
   `map` step of `tools/silicon/silicon_flow.py` (`odin_script`, which runs `abc --gates sky130hd;
   dfflibmap sky130hd`) with the default ABC script replaced by the random one. The ABC mapping
   input is `lib/sky130hd.o3lib` (cells, areas and functions generated from the SKY130 Liberty by
   `tools/silicon/liberty_to_o3lib.py`, Liberty sha256 recorded in the file header, only `_1`
   drive strengths); there is no Liberty importer in the core and no ABC `read_lib`. Odin III
   itself is the existing `odin3/build/rel-main3`, not rebuilt. `obfuscate.map_with_odin` needs a
   fourth kind `silicon` that uses these two commands and `write_blif --gates-as-names`
   (the `gates` branch uses `andornot.o3lib` today).
4. Re-mapping to the same library the Trojan was drawn in is the point: ABC restructures the
   Trojan cone with the surrounding logic, so its cells are no longer an identifiable block.
5. Text finalize as the others: one `.model top`, shuffled ports and cells, every internal net and
   every instance renamed `n<index>` drawn without replacement, no comment or attribute, `conb_1`
   ties for constants. Cell types stay (they are the form); port and clock names stay.
6. Verilog emitted from the finalized netlist. Preferred: Odin III `write_verilog`, then rename
   pass. Fallback: recover each cell from the `.names` function by truth-table match against the
   o3lib. Which one is used is decided in the pilot (a one-cover/one-cell match could be ambiguous
   for functions that two cells share).

Selection effect, as before: a proposal whose Trojan the script removed fails the fire check and is
redrawn.

## 5. Differences from the lut4/lut6 sets (and gates)

| | gates / lut4 / lut6 (comb, seq, proc) | Seeker-Si |
|---|---|---|
| target library | `andornot` 2-input AND/OR/INV, or K-LUT (K=4, 6) | sky130_fd_sc_hd cells, 84 types, up to 4-5 inputs, complex AOI/OAI, mux, xor, maj |
| ABC step | `abc --gates andornot` / `abc --lut K` | `abc --gates sky130hd` plus `dfflibmap sky130hd` |
| sequential cell | generic latch | `dfxtp_1` |
| bases | ISCAS-85/89, ITC-99, VTR, processors | OpenCores designs that pass the silicon map (mmuart, simple_spi, i2c, maybe des) |
| forms | three per golden | one |
| Trojan cells | AND/OR/INV or LUT covers | real std cells (and4, xor2, mux2, dfxtp_1) |
| gate | cec/dsec to lowered netlist, witness in Odin III, FF equality | same engines plus iverilog caveat and `conb_1` handling (section 6) |
| claim | Trojan survives structural obfuscation in logic form | same question at the form a fab sees, and provenance chain exists in the Odin III flow |

## 6. Release gate (as rc2, adapted)

Every circuit file must pass before it is written; any failure stops the build or redraws.

1. Format: one `.model`/module, no duplicate ports, no driven input, no multi-driven net, every
   instance a library cell, Odin III `read_blif` succeeds on the BLIF form.
2. Equivalence to its source by the first engine that proves it: `regmatch-cec`, then `scorr-cec`
   (15 minute cap), then `dsec`. Clean form against the reference design's cell netlist; infected
   form against `pre`, and `pre` with all triggers forced inactive against the reference. A timeout
   is unproven and a failure; the build stops. (wb_lcd shows dsec can be UNDECIDED, hence the
   base table.)
3. Fire: every Trojan of an infected circuit fires on its own witness (Odin III simulation of the
   finished circuit against the reference, payload visible). Fires on trigger only.
4. Silent on neutral stimulus: infected equals clean twin on the design's own testbench stimulus
   where one exists (Odin III two-state sim; iverilog with the sky130 models compared twin against
   twin, not against pass/fail, because of the x values), otherwise a synthetic neutral vector set.
5. FF counts of clean and infected recorded per circuit (answer key); the mapping must not change
   them in a way that leaks the label (checked, reported).
6. Leaks: no seed, magic word, instance name from the inserter, `.attr`, `$` name, base or design
   name in any file next to the circuits; ids opaque and shuffled; structural-signature
   distinctness within a base. Seeds come from `lemanruss.seedsrc` (environment or private file),
   never committed, never in a manifest. Labels, Trojan catalogue, witnesses, scripts, `pre`
   circuits and the net-rename maps live only in `answer_key/`.

## 7. Infected mix and layout

`n_inf ~ Uniform{10..70}` per release, seeded (answer key only), the rest clean, as the n200
design. `releases/seeker-si-v2.0-pilot/` and later: `DATASHEET.md`, `manifest.json`
(`family: silicon`, `bases: [...]`), `circuits/`, `answer_key/` separate. README and results doc
carry the section 0 statement.

## 8. Agent defaults (log, not blockers)

1. One form instead of three (the library is the form).
2. Leak payload built only if it has a replayable witness.
3. des is a phase-3 decision (gate time under the one heavy-run slot).
4. Verilog writer route chosen in the pilot (section 4 step 6).
5. Silence judged twin-vs-twin because of the dfxtp_1 x values.
6. Proc bases excluded: not run through the silicon map.
